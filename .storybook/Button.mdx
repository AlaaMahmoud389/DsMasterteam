# Button

Buttons trigger specific actions. The label describes what will happen when clicked. Choose the variant that matches the action's importance and visual context.

> **Figma source:** [Masterteam DS – Button](https://www.figma.com/design/WTmRAkJVvw0IvZMA7wBdTC/Masterteam-Ds-For-Experiment-ONLY?node-id=4159-296&t=gv8blf425MZ1IhAY-4)
> **DGA Guidelines:** [design.dga.gov.sa/guidelines/components/actions/buttons](https://design.dga.gov.sa/guidelines/components/actions/buttons)
> **Figma node:** `4159:280` · Status: Available

## Overview

Four visual styles · three sizes · six states · leading/trailing/icon-only icon modes · full RTL support · destructive variants. All tokens sourced from Figma node `4159:280`.

## States

Five interactive states. States are driven by user interaction, not set manually. The focus ring is visible only during keyboard navigation.

<Canvas of={ButtonStories.AllStates} />

<Canvas of={ButtonStories.AllVariantsDisabled} />

| State | How triggered | Visual change |
|---|---|---|
| Default | — | Base colors |
| Hovered | `:hover` | Darker background |
| Pressed | `:active` | Darkest background |
| Focused | `:focus-visible` | Double ring: 2px inner (variant color) + 3px outer (white/icon color) |
| Disabled | `disabled` prop | `bg #d2d6db`, `text #6c7c96` — dedicated tokens, not opacity |
| Loading | `loading` prop | Spinner overlaid, label/icons hidden, `aria-busy` set |

## RTL Support

<Canvas of={ButtonStories.RTLAll} />

Pass `dir="rtl"` on the button or wrap it in a `dir="rtl"` ancestor. The button layout flips automatically via logical CSS.

> **Icon mirroring rule:** Directional icons (→ ← chevrons) **must** be flipped in RTL via `transform: scaleX(-1)`. Symmetrical icons (✕ + ⋯) must **never** be flipped.

```jsx
// RTL button — directional arrow icon should be mirrored by caller
<Button variant="primary" dir="rtl" leadIcon={<ArrowRightIcon style={{ transform: 'scaleX(-1)' }} />}>
  الخطوة التالية
</Button>
```

### Icon-only

<Canvas of={ButtonStories.IconOnlyAll} />

When `iconOnly` is set, children are rendered inside the icon slot (no label). **Always provide `aria-label`.**

| Size | Icon dimension | Button w/h |
|---|---|---|
| Large | 24 × 24 px | 40 × 40 px |
| Medium | 20 × 20 px | 32 × 32 px |
| Small | 16 × 16 px | 24 × 24 px |

```jsx
<Button iconOnly aria-label="Add item" size="lg">
  <PlusIcon />
</Button>
```

## Accessibility

- All buttons render as a native `<button>` element — keyboard and screen-reader accessible by default.
- `disabled` sets both the HTML `disabled` attribute and `aria-disabled="true"`.
- `loading` sets `aria-busy="true"` and hides the spinner from assistive technology (`aria-hidden` on `::after`).
- Icon slots have `aria-hidden="true"` — label text is the accessible name.
- Icon-only buttons **must** have `aria-label` (or `aria-labelledby`).
- Focus ring meets WCAG 2.2 Focus Appearance: double ring (2px inner + 3px outer), minimum 3:1 contrast.
- Disabled buttons do not receive pointer events — `cursor: not-allowed` communicates state visually.
- Do not rely on color alone to communicate meaning — pair with label or icon.

## Usage Guidelines

### Do

- Use `primary` for the single most important action on a page or section.
- Use `neutral` or `secondary-solid` for secondary actions alongside a primary button.
- Use `transparent` for low-emphasis actions in toolbars or inline contexts.
- Use `danger` / `danger-secondary` only for irreversible destructive actions (delete, remove, revoke).
- Always label icon-only buttons with `aria-label`.
- Prefer `lg` (40 px) for primary CTAs; use `md` or `sm` for dense UIs.
- Pair destructive buttons with a confirmation step.

### Don't

- Don't put two `primary` buttons next to each other — one action must take precedence.
- Don't use `danger` for non-destructive or reversible actions.
- Don't strip the label without setting `iconOnly` — empty text causes broken layout.
- Don't rely on color alone to communicate meaning — pair with label or icon.
- Don't disable buttons without explaining why (prefer server-side validation or inline errors).
- Don't use `loading` without setting `aria-busy` — the component handles this automatically.

## Code Examples

```jsx
import { Button } from '@/components/Button';

// Primary with lead icon
<Button variant="primary" leadIcon={<ArrowRightIcon />} onClick={handleSubmit}>
  Submit
</Button>

// Secondary-solid, medium size
<Button variant="secondary-solid" size="md">
  Cancel
</Button>

// Danger primary — irreversible action
<Button variant="danger" leadIcon={<TrashIcon />} onClick={handleDelete}>
  Delete account
</Button>

// Danger secondary — softer destructive action
<Button variant="danger-secondary" leadIcon={<TrashIcon />} onClick={handleRemove}>
  Remove
</Button>

// Loading state
<Button variant="primary" loading>
  Saving…
</Button>

// Icon only
<Button iconOnly aria-label="Add item" size="lg">
  <PlusIcon />
</Button>

// RTL Arabic — mirror directional icon manually
<Button variant="primary" dir="rtl" leadIcon={<ArrowRightIcon style={{ transform: 'scaleX(-1)' }} />}>
  الخطوة التالية
</Button>
```
